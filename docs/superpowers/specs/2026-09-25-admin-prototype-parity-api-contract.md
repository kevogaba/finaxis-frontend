## A. Global wire rules

| Rule                                  | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Property names                        | snake_case in every request and response body.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Unknown request properties            | `400 invalid_json` (including camelCase names). Build bodies explicitly.                                                                                                                                                                                                                                                                                                                                                                       |
| Nulls in responses                    | Always present as `null`, never omitted.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `uuid`                                | Canonical lowercase string.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `instant`                             | ISO-8601 UTC with `Z`, e.g. `2026-07-21T10:15:30Z` (fractional digits only when non-zero). All `*_at` fields.                                                                                                                                                                                                                                                                                                                                  |
| `date`                                | `dd-MM-yyyy`, strict (ISO or unpadded values → `400 invalid_json`). Business dates.                                                                                                                                                                                                                                                                                                                                                            |
| Enums                                 | Upper-case names in both directions; unknown values in requests → `400 invalid_json`. Filter values in queries are compared as exact strings, never validated — an unknown value returns an empty page.                                                                                                                                                                                                                                        |
| Missing required fields               | Non-null field absent → `400 invalid_json` (no violations). Present-but-blank or `@NotNull/@NotBlank` nullable field → `400 validation_failed` with violations.                                                                                                                                                                                                                                                                                |
| Idempotency                           | `Idempotency-Key` header: optional canonical UUID (invalid → `400 INVALID_IDEMPOTENCY_KEY`). Echoed on every mutation response; `Idempotency-Replayed: true` on replays. Successful responses replay for 24 h. Same key with a different method/path/body/actor → `409 IDEMPOTENCY_KEY_REUSED`; concurrent duplicate → `409 IDEMPOTENCY_REQUEST_IN_PROGRESS`. A failed mutation rolls back its key, so retrying with the same key re-executes. |
| Other headers                         | `X-Request-Id`; `RateLimit-Limit/Remaining/Reset`; `Location` on 201.                                                                                                                                                                                                                                                                                                                                                                          |
| Collections                           | Always `ApiPage`; `page` 0-based (default 0); `size` 1–100 (default 25); past-the-end pages return `items: []` with correct totals.                                                                                                                                                                                                                                                                                                            |
| Sorting                               | `sort_by` values are **camelCase** from a per-endpoint allow-list; anything else (including snake_case) → 500. `sort_dir` is `ASC`/`DESC` (case per backend parser; send upper-case).                                                                                                                                                                                                                                                          |
| Text search                           | `q` is a case-insensitive substring match; `%` and `_` are not escaped.                                                                                                                                                                                                                                                                                                                                                                        |
| Auth                                  | Missing JWT → `401` problem JSON `authentication_required`. Invalid/expired JWT → `401` with **empty body** and `WWW-Authenticate: Bearer error="invalid_token"`.                                                                                                                                                                                                                                                                              |
| Context                               | `X-Active-Organisation-Context` header: signed (not encrypted) token with user, organisation, membership, branch (or `-`), 8 h fixed expiry. Invalid/expired → `403 invalid_active_tenant_context` (no session fallback). Re-validated on every request: user ACTIVE/INVITED, membership ACTIVE, organisation ACTIVE, and — when a branch is selected — an ACTIVE assignment on an ACTIVE branch.                                              |
| Rate limits (per organisation + user) | `auth-selection` (two `select-*` POSTs) 20/min · `platform-read` / `tenant-read` 600/min · `platform-command` / `tenant-command` 120/min. Full minute's allowance available as a burst. Over limit → `429 rate_limit_exceeded` + `Retry-After`.                                                                                                                                                                                                |

## B. Envelopes

`ApiPage<T>`: `items: T[]`, `page: { number: int, size: int, total_items: int64, total_pages: int,
has_next: bool, has_previous: bool }` (`total_pages = ceil(total/size)`).

`ApiProblem` (`application/problem+json`): `type` (`urn:finaxis:problem:<code>`), `title` (HTTP reason
phrase), `status`, `detail` (safe message), `instance` (path, no query), `code`, `request_id` (your
`X-Request-Id` if sent, else a generated UUIDv7), `violations: ApiViolation[] | null` (≤ 100).

`ApiViolation`: `field` — body errors use the snake_case path with `.` and `[i]` (e.g. `display_name`,
`admin.phone_e164`, `branch_assignments[0].branch_id`); query errors use the parameter name (`size`,
`user_id`, `occurred_from`). `code` — `NotBlank`, `Email`, `Pattern`, `Size`, `NotNull`, `invalid`,
`invalid_parameter`, `missing_parameter`. `message` — DTO message or validator default.

## E. Endpoints, permissions, and semantics

Permission scope: **T** tenant scope (branch-only grants don't count) · **B** target branch (a
TENANT grant or a BRANCH grant at that branch) · **P** PLATFORM organisation. "+ `x.view`" means the
mutation reads its result back and also needs that view permission, otherwise 403 and rollback.

### E.1 Auth — `/api/v1/auth`

| --------------------------- | ------------------ | ------------------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| GET `/organisations`        | `page`, `size`     | ApiPage<AvailableOrganisation> | bare JWT; filtered by `auth.select_organisation` | filtered after paging — `total_items` can overcount                                |

### E.4 Institution-level (no branch selected) versus branch-selected context

- Permissions: a branch-selected context adds BRANCH-scope grants for that branch; institution level
  has TENANT-scope grants only. `auth.select_*` are always checked at tenant scope.
- 404 restrictions apply **only** when a branch is selected: branch detail and transitions,
  branch-assignment get/assign/revoke and list, BRANCH-scope role-assignment assign/revoke at another
  branch. Never branch-restricted: branch list/create, role-assignment list/get, users, memberships,
  roles, permissions, settings, business date, audit, tenant, invite.
- A branch-selected context becomes invalid (`403 invalid_active_tenant_context`) as soon as that
  branch leaves ACTIVE or the user's assignment there is revoked; institution level is unaffected.
- Audit rows written in a branch-selected request get that branch's ID regardless of the branch acted
  on; institution-level requests write null.
