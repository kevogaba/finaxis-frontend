**Date:** 2026-09-25

**Source of truth:** backend source at `/home/ogaba/finaxis/platform` @ `7a7f4c3` (read-only), plus
read-only probes of `https://finaxis-dev.api.ogaba.dev`. The published OpenAPI
(`/v3/api-docs`) has the right paths and query parameters but **wrong property casing** for most

## A. Global wire rules

| Rule                                  | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Property names                        | snake_case in every request and response body.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Unknown request properties            | `400 invalid_json` (including camelCase names). Build bodies explicitly.                                                                                                                                                                                                                                                                                                                                                                       |
| Nulls in responses                    | Always present as `null`, never omitted.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `uuid`                                | Canonical lowercase string.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `instant`                             | ISO-8601 UTC with `Z`, e.g. `2026-07-21T10:15:30Z` (fractional digits only when non-zero). All `*_at` fields.                                                                                                                                                                                                                                                                                                                                  |
| `date`                                | `dd-MM-yyyy`, strict (ISO or unpadded values → `400 invalid_json`). Business dates.                                                                                                                                                                                                                                                                                                                                                            |
| Enums                                 | Upper-case names in both directions; unknown values in requests → `400 invalid_json`. Filter values in queries are compared as exact strings, never validated — an unknown value returns an empty page.                                                                                                                                                                                                                                        |
| Missing required fields               | Non-null field absent → `400 invalid_json` (no violations). Present-but-blank or `@NotNull/@NotBlank` nullable field → `400 validation_failed` with violations.                                                                                                                                                                                                                                                                                |
| Idempotency                           | `Idempotency-Key` header: optional canonical UUID (invalid → `400 INVALID_IDEMPOTENCY_KEY`). Echoed on every mutation response; `Idempotency-Replayed: true` on replays. Successful responses replay for 24 h. Same key with a different method/path/body/actor → `409 IDEMPOTENCY_KEY_REUSED`; concurrent duplicate → `409 IDEMPOTENCY_REQUEST_IN_PROGRESS`. A failed mutation rolls back its key, so retrying with the same key re-executes. |
| Other headers                         | `X-Request-Id`; `RateLimit-Limit/Remaining/Reset`; `Location` on 201.                                                                                                                                                                                                                                                                                                                                                                          |
| Collections                           | Always `ApiPage`; `page` 0-based (default 0); `size` 1–100 (default 25); past-the-end pages return `items: []` with correct totals.                                                                                                                                                                                                                                                                                                            |
| Sorting                               | `sort_by` values are **camelCase** from a per-endpoint allow-list; anything else (including snake_case) → `400 invalid_parameter` with one violation on `sort_by` (6a8ea28; was 500). `sort_dir` is `ASC`/`DESC` in any case, else the same 400 on `sort_dir` (send upper-case).                                                                                                                                                               |
| Text search                           | `q` is a case-insensitive substring match; `%` and `_` are not escaped.                                                                                                                                                                                                                                                                                                                                                                        |
| Auth                                  | Missing JWT → `401` problem JSON `authentication_required`. Invalid/expired JWT → `401` problem JSON `authentication_required` with `X-Request-Id` and `WWW-Authenticate: Bearer error="invalid_token"` (6a8ea28; was an empty body).                                                                                                                                                                                                          |
| Context                               | `X-Active-Organisation-Context` header: signed (not encrypted) token with user, organisation, membership, branch (or `-`), 8 h fixed expiry. Invalid/expired → `403 invalid_active_tenant_context` (no session fallback). Re-validated on every request: user ACTIVE/INVITED, membership ACTIVE, organisation ACTIVE, and — when a branch is selected — an ACTIVE assignment on an ACTIVE branch.                                              |
| Rate limits (per organisation + user) | `auth-selection` (two `select-*` POSTs) 20/min · `platform-read` / `tenant-read` 600/min · `platform-command` / `tenant-command` 120/min. Full minute's allowance available as a burst. Over limit → `429 rate_limit_exceeded` + `Retry-After`.                                                                                                                                                                                                |

## B. Envelopes

`ApiPage<T>`: `items: T[]`, `page: { number: int, size: int, total_items: int64, total_pages: int,
has_next: bool, has_previous: bool }` (`total_pages = ceil(total/size)`).

`ApiProblem` (`application/problem+json`): `type` (`urn:finaxis:problem:<code>`), `title` (HTTP reason
phrase), `status`, `detail` (safe message), `instance` (path, no query), `code`, `request_id` (your
`X-Request-Id` if sent, else a generated UUIDv7), `violations: ApiViolation[] | null` (≤ 100).

`ApiViolation`: `field` — body errors use the snake_case path with `.` and `[i]` (e.g. `display_name`,
`admin.phone_e164`, `branch_assignments[0].branch_id`); query errors use the parameter name (`size`,
`user_id`, `occurred_from`). `code` — `NotBlank`, `Email`, `Pattern`, `Size`, `NotNull`, `invalid`,
`invalid_parameter`, `missing_parameter`. `message` — DTO message or validator default.
Nested list-element fields are non-null, so a missing element field yields `invalid_json`, not a
violation. Bad paging (`size` outside 1–100) yields `400 invalid_parameter` with `violations: null`
on every paged route observed; only `/auth/organisations` (size=0, 101) and `/platform/tenants`
(size=0) were probed live.

**2026-11-24 (6a8ea28):**

- `permission_scopes[] {code, scope, branch_ids?}` (BG-33) says where each code is held: sorted by
  code; `scope` is TENANT or BRANCH; `branch_ids` only on BRANCH (absent, not null, on TENANT),
  every ACTIVE branch the code is held on, not only the selected one; a code held at both scopes is
  one TENANT entry; `[]` for a membership that isn't ACTIVE.
- `missing_view_permissions[]` (role summary and detail): the sorted views the role's held ACTIVE
  mutations need and it lacks (ADR 0030). Reported only: such a role can still be activated.
- `kind`, `grant_scope` and `required_view_permissions` (catalogue, V22): a PLATFORM code is only
  ever evaluated in the platform organisation, so a tenant role holding it gains nothing;
  `required_view_permissions` is sorted and empty for VIEW and CONTEXT.

## E. Endpoints, permissions, and semantics

Permission scope: **T** tenant scope (branch-only grants don't count) · **B** target branch (a
TENANT grant or a BRANCH grant at that branch) · **P** PLATFORM organisation. "+ `x.view`" means the
mutation reads its result back and also needs that view permission, otherwise 403 and rollback.
Since 6a8ea28 (ADR 0030) every mutation needs its own code and each view the catalogue pairs with it
(`required_view_permissions`), at the same scope, checked before any lookup or write; the refusal is
403 `forbidden` naming the first missing code in `detail`.

### E.4 Institution-level (no branch selected) versus branch-selected context

- Permissions: a branch-selected context adds BRANCH-scope grants for that branch to `/auth/me`'s
  `permissions` and to the routes' own `@PreAuthorize` gates; institution level has TENANT-scope
  grants only. `auth.select_*` are always checked at tenant scope.
- Target-aware (6a8ea28, BG-03, platform #154): a selected branch no longer pins administration.
  Branch list and detail, transitions, and branch- and role-assignment search, get, assign and
  revoke, check the permission on the **target** branch, whichever branch is selected: a
  tenant-wide grant, or a grant on that branch, which counts only while that branch is ACTIVE
  (#242). DRAFT, PENDING_APPROVAL and SUSPENDED branches are therefore reachable only tenant-wide,
  and a TENANT role assignment needs a tenant-wide grant. A mutation checks its code **and** every
  view it implies there (`requirePermissionWithViews` / `mutationBranchVisibility`). A branch-scoped
  caller gets 403, never 404, for a branch its grants don't cover (an unknown id included); a
  tenant-wide holder gets 404 for an unknown id.
- Two checks per mutation: the route's own `@PreAuthorize` reads the principal's authorities,
  `effectivePermissions(membership, selected branch)` (the code alone, no views; at institution level
  tenant-wide grants only, refused as 403 `forbidden` with no code named), then the service's
  target check above. So a role held at branches A and B acts on B while A is selected, and on
  neither at institution level. `/auth/me`'s `permissions` is the first check's set, and its BRANCH
  `permission_scopes` list `branch_ids` for every ACTIVE branch, which answers the second.
- Lists are target-aware too: `GET /branches` lists the branches the caller holds `branch.view` on
  (every one tenant-wide, the ACTIVE granting branches otherwise; held nowhere → 403 `forbidden`
  naming nothing), so a branch-scoped caller's totals count its branches only. Role-assignment
  search likewise lists only BRANCH-scope rows at a branch-scoped `role_assignment.view`'s branches.
- Never branch-restricted: branch create, users, memberships, roles, permissions, settings, business
  date, audit, tenant, invite.
- `POST /auth/select-branch` with `{}` or `{"branch_id": null}` returns to institution level, for
  single-branch members too; sign-in (`select-organisation`) still auto-selects a single branch.
- A branch-selected context becomes invalid (`403 invalid_active_tenant_context`) as soon as that
  branch leaves ACTIVE or the user's assignment there is revoked; institution level is unaffected.
- An audit row's `branch_id` is the branch the event is about, not the selected one (6a8ea28,
  BG-16).
